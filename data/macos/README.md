# macOS defaults

`defaults` のドメインを YAML としてこのリポジトリに持つ仕組みです。

## なぜ plist を直接置かないか

macOS の設定 plist は**シンボリックリンクにできません**。cfprefsd がアトミック
置換で書き戻すため、リンクが切れます。そのため `config/` の他のファイルのように
「実ファイル = リポジトリのファイル」にはできず、`defaults export` でコピーする
形になります。

plist の XML をそのまま置くこともできますが、GUI で設定を変えたときに差分を見て
何が変わったか分かるようにしたいので、YAML に変換しています。

## 使い方

```bash
make macos-diff     # リポジトリと実機のどこが違うか
make macos-export   # 実機 -> リポジトリ
make macos-import   # リポジトリ -> 実機
```

`macos-diff` は差分があると終了コード 1 を返すので、CI やフックから使えます。

GUI で設定を変えても自動では記録されません。`make macos-diff` を叩いたときに
初めて分かります。

## 管理対象

`config.yaml` の `domains` に書いたドメインを**丸ごと**ミラーします。キーを手で
選ばないのは、選んだ時点で「思いついた設定しか気づけない」ようになるからです。

## exclude

`config.yaml` の `exclude` に書いたキーは、

- **export 時**: 無視される（YAML に書き出されない）
- **import 時**: 実機の値をそのまま残す（上書きも削除もしない）

ここに入れていいのは2種類だけです。

- 誰も決めていないのに変わる揮発的な値（タイムスタンプ、カウンタ、ウィンドウ座標）
- このマシンでしか意味を持たない値（ディスプレイ UUID、デバイス ID）

**他のマシンでも欲しい設定は、どれだけ差分がうるさくても exclude に入れないで
ください。** そのうるささが目的です。

キーはシェル glob で書きます。トップレベルのキー名に対して照合されます。
`"*"` の下に書いたものは全ドメインに適用されます。

## 挙動の細かい話

- **削除も反映されます。** `defaults import` はマージなので、リポジトリから消えた
  キーは `defaults delete` で個別に消しています。exclude されたキーは対象外です
- **バイナリ値も往復します。** plist の data は YAML の `!!binary`、plist の date は
  YAML のタイムスタンプになります
- **キーはソートされます。** アプリがプロパティの順序を入れ替えただけでは差分に
  なりません
- **Dock のアプリ配置も対象です。** `persistent-apps` には各アプリの `book`
  (バイナリ) と `file-mod-date` が入っているので、アプリが更新されると差分が出ます
- `import` の後は、対象アプリの再起動かログアウトが必要です

## 依存

`python3` と PyYAML。ansible が PyYAML を要求するので、このリポジトリの
セットアップを通したマシンには入っています。
